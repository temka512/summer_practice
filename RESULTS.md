## Анализ результатов

На основе полученных таблиц и графиков можно выделить следующие закономерности.

### Поведение алгоритмов по сложности

**Алгоритмы O(n²)** (пузырёк, выбор, вставки) демонстрируют ожидаемый квадратичный рост времени. Для N = 5000 время выполнения составляет единицы секунд, а для N = 1000 – сотые доли секунды. На размерах N ≥ 50 000 они не запускались из-за слишком долгого времени (более нескольких минут).

На уже отсортированных данных вставки работают почти линейно (лучший случай O(n)) – время для Sorted практически не растёт с увеличением N. На обратных данных пузырёк и выбор работают хуже всего (максимальное число перестановок), в то время как вставки также показывают квадратичное время, но немного быстрее на случайных данных.

**Алгоритмы O(n log n)** (быстрая, слияние, куча) масштабируются значительно лучше. При N = 1e6 время колеблется в диапазоне 0.3–25 с в зависимости от типа данных и интерпретатора.

Быстрая сортировка показывает наилучшее среднее время на случайных данных, но на уже отсортированных или обратных данных (если опорный элемент выбирается неоптимально) время может ухудшаться. В нашей реализации опорный элемент – средний по позиции, поэтому на отсортированных данных быстрая сортировка может деградировать до O(n²) (это видно по резкому росту времени на Sorted для Quick).

Сортировка слиянием стабильно показывает O(n log n) на всех типах данных, так как всегда делит массив пополам. Её время примерно одинаково для всех типов данных.

Пирамидальная сортировка также устойчива, но немного медленнее слияния из-за более сложных операций с кучей.

**Линейные сортировки** (подсчёт, поразрядная, корзинами) демонстрируют наилучшее время (менее 0.1 с для N = 1e6 на PyPy), но их применимость ограничена целыми числами и диапазоном значений. На CPython они также показывают хорошие результаты, но требуют дополнительной памяти.

- Сортировка подсчётом работает быстро, но требует дополнительной памяти, пропорциональной размаху значений.
- Поразрядная сортировка показывает стабильное время, не зависящее от типа данных.
- Сортировка корзинами хорошо работает на равномерно распределённых случайных данных, но может деградировать на отсортированных (если все значения попадают в одну корзину).

**Встроенная `sorted()`** – безусловный лидер по скорости (в 2–5 раз быстрее ручных реализаций). Это объясняется тем, что она написана на C и использует алгоритм Timsort, который адаптируется к структуре данных. На почти отсортированных данных она показывает практически линейное время.

### Влияние типа входных данных

- **Random** – все алгоритмы работают в среднем случае, что соответствует теоретическим оценкам.
- **Sorted** – преимущество получают алгоритмы, которые используют упорядоченность: вставки, Timsort. Быстрая сортировка без рандомизации опорного элемента показывает наихудшее время.
- **Reversed** – аналогично Sorted, но вставки работают хуже (квадратичное время), так как каждый элемент нужно перемещать в начало.
- **AlmostSorted** – вставки и Timsort почти не замедляются по сравнению с Sorted, так как требуется лишь несколько перестановок.

### Сравнение интерпретаторов: CPython vs PyPy

PyPy даёт значительный прирост скорости для **чистого Python-кода** (особенно для циклов). Например, для пузырька на N=1000 время на PyPy (~0.0009 с) значительно меньше, чем на CPython (~0.385 с) – ускорение более чем в 400 раз! Это связано с тем, что PyPy использует JIT-компиляцию и эффективно оптимизирует циклы.

Для алгоритмов с рекурсией (быстрая, слияние) ускорение также заметно – Quick на N=1e6: CPython ~6.17 с, PyPy ~0.66 с (ускорение ~9 раз).

Встроенная `sorted()` на PyPy работает примерно с той же скоростью, что и на CPython, потому что она реализована на RPython (внутреннем языке PyPy) и хорошо оптимизирована, но всё же уступает реализации на C в CPython (PyPy ~0.14 с, CPython ~0.185 с на Random N=1e6).

По памяти – PyPy потребляет больше памяти из-за особенностей JIT-компиляции и сборки мусора. В наших измерениях tracemalloc был доступен только для CPython, поэтому для PyPy значения памяти отсутствуют.

### Подтверждение теоретической сложности

Графики в логарифмическом масштабе наглядно показывают наклоны линий:
- Для O(n²) наклон равен примерно 2 (при увеличении N в 10 раз время растёт в 100 раз).
- Для O(n log n) наклон чуть больше 1.
- Для O(n) наклон близок к 1.

Это полностью соответствует теории.

### Итоговые выводы

1. Для больших объёмов данных (N > 10 000) предпочтительны O(n log n) или линейные алгоритмы.
2. Если данные почти отсортированы – лучший выбор – встроенная `sorted()` или сортировка вставками (для небольших N).
3. PyPy может существенно ускорить выполнение пользовательских алгоритмов (в десятки и сотни раз), но проигрывает CPython во встроенных функциях.
4. При разработке на Python для реальных задач всегда стоит использовать `sorted()` или `.sort()` – они оптимальны почти для всех случаев.

## Инструкция по воспроизведению

### Требования

- Операционная система: Windows (также работает на Linux/macOS).
- Установленные интерпретаторы:
  - CPython версии 3.11 или выше.
  - PyPy версии 7.3.17 или выше.
- Установленные пакеты Python: `pandas`, `matplotlib`.

Установите пакеты командой:
```bash
pip install pandas matplotlib
```

### Шаги для запуска

1. **Перейдите в папку src:**
   ```bash
   cd src
   ```

2. **Запустите бенчмарк для CPython:**
   ```bash
   python run.py --interpreter CPython --output ../results/results_cpython.csv
   ```

3. **Запустите бенчмарк для PyPy:**
   ```bash
   pypy run.py --interpreter PyPy --output ../results/results_pypy.csv
   ```

4. **Объедините результаты** в один CSV-файл:
   ```bash
   python merge_results.py
   ```

5. **Постройте графики:**
   ```bash
   python plot.py
   ```

### Примечания

- Для ускорения бенчмарка можно уменьшить список размеров в файле `run.py`.
- При первом запуске процесс может занять несколько минут (особенно для N=1e6).

## Ограничения

- Алгоритмы O(n²) не запускались для N > 5000 из-за слишком долгого времени выполнения.
- Сортировка подсчётом и поразрядная работают только с целыми числами.
- Измерение памяти через tracemalloc недоступно в PyPy (значения помечены как N/A).
- Сортировка корзинами оптимальна только для равномерно распределённых данных.
- На CPython сортировка корзинами на N=1e6 для Reversed показала аномально высокое время (~385 с) – это связано с тем, что все элементы попадают в одну корзину.
